## 3. 本地环境准备（最容易踩坑的一步）

### 3.1 MySQL 必须是 8.x

**不要用禅道自带的 MySQL 5.5。** 那台实例的 InnoDB 被禁用，建日志表会直接失败（`Unknown storage engine 'InnoDB'`）。

### 3.2 端口默认 3307

`backend/src/config.ts` 与 `.env.example` 里 `DB_MASTER_PORT` / `DB_SLAVE_PORT` 默认都是 **3307**。两种做法任选：

- 把 MySQL 起在 3307；
- 或在 `backend/.env` 里改成你自己的端口（如 `DB_MASTER_PORT=3306`）。

`.env` 已被 gitignore，**不要提交**。

### 3.3 建库 + 建表

```sql
CREATE DATABASE IF NOT EXISTS scenic_ai DEFAULT CHARSET utf8mb4;
```

然后导入：

| SQL 文件 | 作用 | 是否必须 |
|---|---|---|
| `backend/sql/01_schema.sql` | 业务主表（poi / route / admin_user 等） | 业务功能必须 |
| `backend/sql/03_log_schema.sql` | 三张日志表 | 可选，后端启动时 `initTables()` 会自动建（幂等） |

`admin` / `admin123` 账号由后端首次启动自动创建，无需手工插入。

### 3.4 Redis 可选

`.env.example` 默认 `REDIS_ENABLED=false`，此时日志**直写 MySQL**，功能完全正常，只是少了「异步削峰」的演示效果。

要演示 Redis Stream，装 Memurai / Docker `redis:7`，然后：

```env
REDIS_ENABLED=true
REDIS_URL=redis://127.0.0.1:6379
REDIS_LOG_STREAM=scenic:log:stream
REDIS_LOG_GROUP=log-writer
```

## 6. 接口契约

### 6.1 上报（公开，无鉴权）

| 接口 | 必填字段 | 说明 |
|---|---|---|
| `POST /api/v1/logs/operation` | `resourceId`、`resourceType` | `action` 默认 `click`，`pagePath` 默认 `/` |
| `POST /api/v1/logs/error` | `errorMessage` | `errorName` 默认 `Error`，`stack` 上限 4096 |

两条都是 best-effort，前端不阻塞、失败不重试。**traceId 只认请求头 `X-Trace-Id`**，body 里的 `traceId` 字段不生效。

### 6.2 查询（需管理员）

```
GET /api/v1/logs/operation?page=1&pageSize=20&traceId=&userId=&apiPath=&method=&start=&end=
GET /api/v1/logs/error?page=1&pageSize=20&traceId=&errorType=
GET /api/v1/logs/login?page=1&pageSize=20&username=&loginResult=
GET /api/v1/logs/trace/:traceId
```

```bash
curl -H "Authorization: Bearer 1:admin:admin" -H "x-user-role: admin" \
  "http://localhost:8000/api/v1/logs/operation?page=1&pageSize=5"
```

> ⚠️ 查询接口目前仍用 `backend/src/routes/authGuard.ts` 这个**占位守卫**：任意非空 Bearer 都能过，角色只看 `x-user-role` 头。C 的 JWT 鉴权落地后，这里要换成 `middleware/auth.ts` 的 `requireAuth + requireRole('admin')`，见该文件顶部 TODO。

## 7. traceId 约定（全组统一）

1. 前端 `apiClient` 从 `localStorage.traceId` 取值 → 请求头 `X-Trace-Id` 发出；响应头有值时回写 localStorage，所以**同一个页面会话共用一个 traceId**。
2. 后端 `normalizeTraceId()` 校验：长度 ≤ 64，只允许 `[A-Za-z0-9._-]`；不合法就丢弃并生成 UUID。
3. 响应头 `X-Trace-Id` 必须能被浏览器读到，`app.ts` 的 CORS 已配置 `exposedHeaders: ['X-Trace-Id']`，**这行不要删**。
4. 前端埋点用的是裸 `fetch`（不走 apiClient），所以 `track.ts` 里必须手动带 `X-Trace-Id` 头 —— 本次已补。

自查：`GET /api/v1/logs/trace/<traceId>` 能同时看到操作 + 错误 + 登录三类记录，才算链路通。

## 8. 不要动的地方（改之前先问 B）

| 约束 | 原因 |
|---|---|
| **Express 不能升 5.x** | 5.x 的 SSE 行为变化会打断大屏 / TTS 流式输出，本项目锁定 `4.21.0` |
| `app.ts` 中间件顺序：`traceId → auth → operationLog → 业务路由 → errorHandler` | errorHandler 必须在最后；operationLog 必须在这两者之间，否则 traceId / user 拿不到 |
| 日志接口 `POST /logs/*` 必须在 `router.use(requireAuth...)` 之前注册 | 前端埋点不带 token，放后面会 401 |
| 脱敏不可逆 | `mask.ts` 只保留首尾字符，日志里查不到原文，这是设计要求 |
| 新增业务路由不用额外写日志 | 只要挂在 `/api/v1/*` 下，`operationLogMiddleware` 会自动记录 |

已跳过、不会记操作日志的路径：`/api/v1/auth/login`、`/api/v1/auth/refresh`、`/api/v1/auth/register`、`/api/v1/logs/*`、`/health`（登录另走 `login_log`）。

## 9. 排错 FAQ

**Q1：三张日志表一直是 0 条**
- 看后端启动日志有没有 `logs 数据表初始化跳过（MySQL 不可用）`；
- 检查 `.env` 端口 / 密码是否对（默认 3307）；
- 检查是不是 MySQL 5.5（InnoDB 被禁用）。

**Q2：数据写进去了但查询接口报 500**
- 查询走的是读库（`DB_SLAVE_PORT`），本地没做主从时它要和主库端口一致。

**Q3：Redis Stream 有 pending 一直不消费**
- 消费者落库失败时**故意不 ACK**，避免日志静默丢失；
- 修好 MySQL 后重启后端；要彻底重来就 `DEL scenic:log:stream`（重启会自动 `MKSTREAM` 重建消费组）。

**Q4：埋点返回 400**
- `/logs/operation` 要 `resourceId` + `resourceType`；`/logs/error` 要 `errorMessage`。字符串超长（>512）会被判非法。

**Q5：日志查询 403**
- 占位守卫按 `x-user-role` 判角色，记得带 `x-user-role: admin`。

**Q6：`user_id` 一直是 null**
- 只有带合法 JWT 的请求才有用户；埋点接口是公开的，需要前端在 body 传 `userId`。
